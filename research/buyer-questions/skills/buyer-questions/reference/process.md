# Process notes

## Buyer calls

Recorders mislabel speakers in both directions. Split each call into numbered turns and judge each speaker from what is said. Keep quotes only from buyer turns. Anonymize call labels for anything you publish. Product claims you hear in demos go to an internal note, not into the set.

If you can, add two standing questions to every future sales call: which AI tool do you use, and what were the last five things you asked it. It is the only record of real buyer prompts.

## Grading by askers

| Grade | Rule |
|---|---|
| confirmed | 2 or more independent askers outside the vendor side |
| hypothesis | 1 asker |
| tool-only | no asker, only keyword tools or the team's own list |

A thread that looks planted by a vendor counts as one asker. Someone who works at a competitor, or who does not buy, counts as 0. Influencers are an audience, not a buyer.

## Phrasing

Rewrite each question in the asker's register. Pain questions read in first person and run 25 to 40 words. Others run 10 to 20 words. Say no more than the quotes say. Never name the company.

## The gap check

Run each question through several assistants, once with search on and once with search off. Search off tests what the model knows. Search on tests who answers. Use a search engine signed out for the third view. Do not use an assistant's built-in search as a stand-in for the search engine.

| Mark | Meaning |
|---|---|
| nobody | refuses, or answers another question |
| thin | the right question, nothing the buyer could act on |
| not for this buyer | a real answer for someone else (another size, another stack) |
| exactly for this buyer | what the company would say, for this buyer, at this moment |

If two or more assistants answer "exactly" and the answer matches a pillar of the company's position, tell whoever owns the positioning before you write. The pillar is already stated. Use it as proof inside pages.

Marks over-fire when the prompt carries a line about the buyer's situation. Read the openings from the reviewer's notes.

## Freeze rules

The measured set is a sample. A single question's reading is mostly noise, so more distinct questions help more than more repeats. The set stays small enough to read. Changing more than about 10% of it changes the panel, so treat that as a new baseline. Questions join later in small dated batches.

## Coverage map

A page answers a question when one answer on it would satisfy the asker. Check that with a quote from the page. Mark partial answers as partial. Plan new pages in waves, and keep some topics unpublished at first so they act as a comparison for the ones you did publish.
